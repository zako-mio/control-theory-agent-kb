## 一、任务定位

在现有「控制理论 ⊗ Agent 设计知识库」（v1.0，6 产品版）基础上，扩展**市面主流「精装房」 Agent 产品全景**（跨 4 大类、约 11 个典型产品（最终交付 14 款，见 report-v1.1）），并**对全部产品（现有 6 + 新增）进行再分类**。

**核心命题**：来自用户核心洞察 ——「**声称 ≠ 实际**，源码分析能看出真正的一手还是二手」。实证鉴别每款产品的真实性质。

---

## 二、核心分析坐标系（四维）

| 维度 | 定义 | 作用 |
|------|------|------|
| **精装度（主轴）** | 0-5 分，预装程度（多Agent编排/skill库/MCP生态/一键接入/预装workflow/记忆） | 主排序列，标注每产品在「毛坯→豪装」谱系的位置 |
| **一手/二手（标签）** | 供应方是否原创 | 一手=自研原创；二手=封装/转卖底座 |
| **4 大类（分组）** | 第一方成品 / 二次封装 / 低代码平台 / 开源成品化 | 参考分组 |
| **五环定位** | M记忆/P规划/R反思/T工具/E评估 | 控制工程本质 |

> ⚠️ 关键概念区分：「一手/二手」与「精装/毛坯」是**正交的两根轴**，不可混。
> - 精装/毛坯 = 预装了多少（精装度）
> - 一手/二手 = 供应方是否原创者
> - 毛坯房也可以是二手（开源壳包装发版）；精装房也可能是一手（大厂自研成品）

## 四、实证深度策略

- **开源源码级验证**：依赖/入口/是否包壳/预装能力（机制级）
- **闭源文档优先 + 黑箱行为兜底**：公开文档为主，黑箱行为测试仅在有免费额度/无需密钥时做，**不申请任何 API 密钥/授权**（规避红线）
- **证据强度分级**：源码级 > 文档级 > 行为级 > 声称级

## 六、关键约束（红线）

1. **闭源全部文档优先**，**不申请任何 API 密钥/授权**
2. **人类可读 HTML 为唯一成果重心**（用户只看高可读 HTML）；AI 端 MD 镜像/审计报告为低优先配套（仍生成，不重点关注）
3. **契约红线**：仅 `/tmp/opencode` 实机黑箱 + 源码只读；不改记忆系统文件；不做不可逆破坏
4. **复用**：render_case.py / gen_html.py / gen_dag_data.py / 门控脚本 / design-tokens.css
5. **违约回退**：源码能做的做到机制级，做不到的用文档+行为分级标注，不强求统一
