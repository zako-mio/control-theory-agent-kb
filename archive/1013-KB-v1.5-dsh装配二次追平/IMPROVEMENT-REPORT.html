KB v1.5 改进方向建议报告 — 从「dsh 装配层二次追平」实测出发

性质：建议报告（非 5 段任务留档；本文件与 report-execution.md 互补——后者记录「做了什么」，本文件回答「下一步该改什么」）。 依据：2026-10-13 完成的 KB v1.5 轮次（R1–R12 追平 + 三条旧结论重判 + 实验 15–18 本库自跑）。 原则：每条建议都必须挂在本轮实测到的证据上；无证据的「想当然改进」一律不进正文（见 §5 负向建议）。

1. 背景与依据：本轮实测暴露了什么

1.1 被推翻的三条旧结论（说明「结论存续性」需要例行检查）

#v1.4 旧结论本轮实测性质
C1本机无可用沙箱后端 → 一律 fail-closed三档 enforcement=full、argv0=bwrap，真 spawn + 真写盘（实验 17）环境事实反转
C2R 环迁移断裂、最弱环 R = 3.0候选↔正文段 14/14 成立，容量 band=soft（实验 16）结论推翻
C3子 Agent 无 bash ⇒ E 环只判增强门控通道 57/57 + 23/23 + 10 变异体全判死（实验 15）抑制项消解

推论：知识库的「结论」有保质期，且过期是静默的。若只做「刷新 evidence」，错误结论会被原样继承。

3. 分域改进方向

3.1 域 A — DSH 装配层（分析对象的改进）

A-1（I-7）补完行为验收的最后一段 — 现状：实验 15–18 已自跑证明机制真实行为（脚本 / 进程 / 文件级）；preset 会话内的模型行为仍空白（命令面板是否列出 /arch /rd /reflection、skill 是否被自动加载、oc_reflection 是否在真实会话中产出候选）。建议：由用户各开一条会话验收，判据＝「命令面板三条可见 + 该回合日志出现 command/run + 加载正确的那一件 skill」。注意判读纪律：同会话内后一题未再加载 skill 不算未命中。

A-2（I-8）治「死配置」 — 现状：verify_dsh_config.py C3 报 9 条 note（base 层设了键，赢家层 config 里没有 ⇒ 整块替换后不生效）。这类缺陷无报错、无告警，是配置层最危险的一类。建议：逐条裁决「删除 / 上移到赢家层 / 显式声明为有意为之」，并把这 9 条纳入下一轮的写面声明。

A-3（I-9）persona 的差异化与预算 — 现状：6524 字符 × 3 preset 全量复制；ptc 模式下工具面坍缩为单 run_code，而 persona §二 仍写「本模式提供 subagent、oc_explore…」（v1.4 实测的空指向，本轮未复测）。建议：① 按 presentation mode 分支 persona 的委派段；② 把「只在某 preset 生效」的段落下沉到该 preset 的 section，而非三份复制。

A-4（I-10）可移植化 — 现状：bundle 含本机绝对路径、node_modules 符号链接指向本机源码树 ⇒ 8 维「一键部署」永久封顶 3。建议：路径抽为配置项、依赖改走 npm 声明；验收判据＝在另一台机器上 install_bundle 后 verify_bundle 20 项全过。

A-5（I-11）E 环覆盖域扩张 — 现状：E 环 Δ+2.0 已达反转阈值，但覆盖仅架构 / 需求两域（故未取 4.5+）。建议：按「领域任务是否高频」排序，逐域补门控脚本（判据须绑被消费字段而非整文件指纹——v1.4 假阳性的教训）。

A-6（I-12/I-13）R 环与 MCP 的下一档 — R 环现为显式链（非自动自省）；MCP 宿主 0 配置。建议：① 为 R-B（结构化队列）/ R-C（会话边沿自动审阅）写明切换触发条件（ADR-012 已列为后置选项），避免「什么时候该升级」再次变成人记；② MCP 只在有真实工具面缺口时接入（PDF / 出图已由 skill 替代，不宜为凑分而接）。

3.2 域 B — 知识库工程（KB 自身的改进）

B-1（I-1）空集守卫：本报告最高优先级 — 现状：coverage 层曾「检查项=0 却 PASS」。建议：给 kb_gate.py 全部计数型判据加统一守卫：checked == 0 ⇒ FAIL（附白名单机制，允许显式声明「本层本轮无对象」）。验收判据＝构造一个「对象集为空」的夹具，该层必须 FAIL。

B-2（I-2）交付物引用存在性门控 — 现状：子 Agent 编造了 verify-bundle-20checks.out.txt 并写进公开画像（主 Agent 复核才发现）。建议：新增一层（或并入 sources 层）扫描所有 MD/HTML 中的反引号路径与 evidence/ 引用，逐个 stat；不存在的路径 ⇒ FAIL。这条能把 D3 从「靠人复核」变成「机检拦截」，是本轮最有价值的结构性改进。

B-3（I-3）口径一致性机检 — 现状：skill 计数四套读数并存两轮，本轮才写入契约。建议：在 kb_gate.py 增一条「口径一致」检查：README / 变体画像 / 快照 inventory.json 三处的 skill 计数必须一致（口径定义以契约 §2.6 为准）。判据锚点必须落在快照（唯一机械承载），而非文档。

B-4（I-4）陈旧数值扫描门控 — 现状：本轮手工跑了「3.6→3.8 / Δ+0.2 / 旧页脚」的残留扫描（结果 0）；v1.5 收尾时又靠读图才发现门户卡片残留旧值。建议：把该扫描固化为 cascade 层的一条规则（带历史块豁免），避免依赖「碰巧看见」。

B-5 视觉层的取证件标准化 — 现状：L4 由主 Agent 读图，取证件落在 07-checkpoint/l4-v1{N}/。建议：固化命名与「哪几页必看」的清单（本轮为 compare / case / portal 三页），并把「读图结论」写成可归档文本，避免 L4 成为唯一无判据的门控层。

3.3 域 C — 流程与协作（跨轮次改进）

C-1（I-5）静止点判定三步法 — 现状：本轮因分析对象是动目标而中途暂停。建议写入契约并作为例行节奏：① 判据脚本两次读数一致；② 上游线进入收官轮；③ 本库无并发写入。三项通过才取证据，且所有读数带 as_of。

C-2（I-6）实验 provenance 分列 — 现状：实验 15–18 的自跑结果与「他线实跑取证引用」曾在同一节混列。建议：实验模板加 provenance 字段（本库自跑 / 他线引用 / 环境事实），并在报告里分列呈报——⛔ 不得以脚本级自跑冒充行为验收。

C-3 子 Agent 交付物复核清单（把 D3/D4 前置拦截） — 现状：本轮主 Agent 复核抓到 2 类缺陷。建议：委派时即给「返回契约附加项」——① 引用路径必须逐条 stat 过；② 数值必须注明来源文件与行号；③ 主 Agent 复核时优先抽查「新引入的路径」与「与上轮相同的数值」（这两处最易出错）。

C-4（I-14）跨线同名治理 — 现状：两条线各有一个 ADR-011。建议：ADR 编号加域前缀（如 ADR-MIG-011 / ADR-FED-011）或强制路径限定；后者本轮已立为引用纪律，但根因未除。

4. 落地路线与验收判据

阶段内容验收判据
第 1 步（可立即做，纯 KB 侧）I-1 空集守卫 + I-2 引用存在性门控 + I-3 口径一致性 + I-4 陈旧数值扫描四项各配负向夹具（构造违规输入 ⇒ 必须 FAIL）；全库复跑仍 ALL PASS
第 2 步（需你 2 条会话）I-7 preset 行为验收命令面板三条可见 + 日志出现 command/run + 加载正确 skill
第 3 步（装配层小改）I-8 死配置裁决 + I-9 persona 分支verify_dsh_config.py C3 note 归零或有书面裁决；ptc 空指向消失
第 4 步（下一轮 v1.6 主题）I-11 E 环扩张 / I-10 可移植化 / I-12 R 环升级条件按 §2 优先级逐项立项，各自带判据

通用验收纪律（承本轮教训）：任何新增判据必须先答两问——「它的真值来自哪里」「它在什么输入下会 FAIL」。答不出即视为恒真，⛔ 不得计入形式齐备证据。

5. 不建议做的事（负向建议）

  1. 不要重设既有阈值（零和预算 / 生命周期五件 / 容量硬软限）——本轮 R-A 载体已「逐字承接」这些口径，重设＝制造第二套标准。
  2. 不要为凑分接入能力（如为 MCP 维补分而接 MCP）——档位判的是「真实可扩展成本」，不是计数。
  3. 不要把环境事实计入装配层收益（沙箱 enforcement=full 是环境变化，本轮已冻结分值）。
  4. 不要以脚本级自跑冒充行为验收（preset 会话内的模型行为只能由人开会话测）。
  5. 不要手工改生成物（本轮已把 fix_cyto.py 改为幂等，避免「改了生成物、忘了脚本」的复发）。
  6. 不要新建第二真相源（口径的唯一承载是 snapshot_dsh_custom.py；ADR 正文留在迁移线，KB 只存指针）。
  7. 不要靠「提醒仔细点」解决 D3/D4 —— 编造引用与过时读数必须由机检拦截，否则每轮都会复发。
