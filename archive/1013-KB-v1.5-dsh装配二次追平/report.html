5. 反思 / 分析 / 建议

5.1 过程反思

  1. 「重新分析」不能默认成「刷新数字」。摸底后发现三条 v1.4 结论已被推翻（沙箱、R 环、E 环口径），若按维护性刷新处理，会把错误结论原样带到 v1.5。⇒ 复评前先做「结论是否仍成立」的判定，比直接重算分值更重要。
  2. 动目标是本轮最大的方法学风险。分析对象（dsh 装配层）在分析期间被另一条线持续改写；若不先定静止点，「证据层全量重算」会在数小时内失效。这属于「先问时序、再问内容」的典型。
  3. 口径必须先归一。同一事实出现四套读数（skill 45 / 46 / 47 / 49），不是记录不勤，而是缺少「唯一权威口径」的约定；在没有唯一口径前做复评，各维度分值不可比。
  4. 子 Agent 工具面须先探明：本轮把「跑 diff/stat」委派给了只读探索 worker，而该 worker 无 shell，导致委派部分降级。⇒ 委派前先确认 worker 能力面，机械比对类任务应由主 Agent 用 shell 承担。

5.2 收获认知

  1. 装配层复评的「三条独立轴」：机制新增（有无）、能力纵深（够不够）、结论存续（旧判断是否仍成立）。第三条最容易被忽略，却最容易造成事实错误。
  2. 备份文件名即时间线：<名>.bak-<原因>-YYYYMMDD-HHMMSS 的命名惯例使轮次重建无需版本控制即可完成——这是可复用的取证资产。
  3. 「文档自述」与「磁盘实况」会分叉：本轮实测到至少 2 处（README §5 的 defaultPreset 陈旧、README 自标「45 件已过期」）。⇒ KB 这类以自述为主的产物，复评时必须把「实况读数」作为第一顺位证据。
  4. 两条线共名会制造歧义：0928 线与迁移线各有一个 ADR-011。跨线引用必须带路径限定，否则深链会指向错件。
