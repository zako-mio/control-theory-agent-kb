5. 反思 / 分析 / 建议

5.1 过程反思

  1. 「重新分析」必须先判「旧结论是否仍成立」。本轮三条 v1.4 结论（沙箱 / R 环 / E 环）全部被现实推翻——若按维护性刷新处理，会把错误结论原样带进 v1.5。判定顺序应是「结论存续 → 机制有无 → 能力纵深」，而非直接重算分值。
  2. 动目标是分析类任务最贵的方法学风险。先定静止点再取证据，比先取证据再发现过期便宜得多；as_of 标注与「他线可能并发变更」声明应成为此类任务的标配。
  3. 口径不统一会让复评失去可比性。skill 计数四套读数困扰了两轮；本轮把口径写入契约并指定唯一机械承载（脚本），是可持续的解法——⛔ 只改文档数字不解决问题。
  4. 子 Agent 的交付物必须由主 Agent 逐项复核。本轮实测到两类缺陷：编造取证件名（凭空推导出一个不存在的文件名）与过时读数（沿用上一轮的数字）。两者都不是格式问题，而是证据链完整性问题；若不复核会直接污染公开知识库。

5.2 收获认知

  1. 「环境事实」与「装配层收益」必须分账。沙箱从「无后端」到 enforcement=full 是真实变化，但归因在环境而非装配层；把它计入分值就是虚报。本轮将其单列为「口径变更披露」并冻结分值。
  2. 空集假绿是最隐蔽的判据失效形态。checked=0 却 PASS，比判据报错更危险——它让「全绿」失去意义。修复方式是补参数 + 负向控制，并把「计数型判据为 0 即 FAIL」写入纪律。
  3. 迁移损失的「追平」比「新增」更有信息量。R 环由断裂到接通、E 环由只判增强到反转，都来自对旧结论的正面推翻；这类结论应显式登记（历史块 + 结论变更表），而不是静默改写。
  4. proposed 状态的 ADR 仍可作证据，但引用时必须如实标注状态；KB 只登记指针、不复制正文，既守住公开库边界，又保留可追溯性。

5.3 建议

  1. 下一轮（v1.6）建议把「装配层追平」做成例行节奏（如月度），并在契约里固化「静止点判定」三步法（判据脚本两次读数一致 / 上游线进入收官轮 / 本库无并发写入）。
  2. 建议补做 v1.5 新机制的行为实验（N1–N4 的自跑版）：最小启动条件已登记在 06-experiments/dsh-custom.md，需用户开 opencode-creator 会话或显式放行 /tmp 隔离区复跑。
  3. 建议把「他线实跑取证引用」与「本库自跑实验」在实验模板里分列标记，避免读者把引用当自证。
