实验1 正常基线（纯推理）

实验设计
  • 控制组无；实验组为隔离 config（无 instructions / 无 MCP / 无 skills）下 --agent orch 的纯推理任务；观测指标为输出正确性、收敛轮数、token 与成本、是否触发外部协议。
执行数据
  • 命令 opencode run "用一句话解释什么叫负反馈控制" --agent orch --format json；环境 XDG_CONFIG_HOME=/tmp/opencode/iso-config，模型 deepseek/deepseek-v4-flash，opencode 1.18.29；时间戳 2026-09-09 01:40:34→01:40:40（耗时 5.77s），会话 ses_f7de47c42ffeNikJxKaLVIXn4D。
观测结果
  • 输出为「负反馈控制是指系统通过检测输出与期望值的偏差，并将该偏差反向作用于输入以减小误差，从而自动维持输出稳定的控制方式。」；正确性 ✅（单句、定义完整、无冗余）；1 轮收敛，无工具调用，无外部协议介入。
量化指标
  • 计划进度偏差 1/1 步（无偏航）；token total 5645（input 5537 / output 32 / reasoning 76）；成本 $0.000805；反馈信噪比高（一次直出）。
控制论解读
  • 属于设定值 r + 开环直出（E 环由人判断达标）；控制律为单次前馈（feedforward），无反馈回路。基线证明隔离态下内核可独立完成任务，为后续实验提供无协议干扰的参照系。

实验2 专职 worker 委派（P 环强化）

实验设计
  • 控制组为实验1（单 agent 直出）；实验组在隔离 config 定义 orch(primary) + general/explore(subagent) 且 subagent_depth=2，用一次 prompt 要求同一消息内并行发出两个 task；观测指标为是否委派、是否并行、委派链深度、聚合正确性、轮数。
执行数据
  • 命令 opencode run "请并行委派两个子任务：①委派 general 计算 17×23；②委派 explore 统计 /tmp/opencode 条目数……" --agent orch --format json；时间戳 01:40:43→01:40:57（14.49s）；父会话 ses_f7de45b7affeIfMveMoZBV5ckG；委派链 orch → task(general)=ses_f7de44e21ffecfmA6NzkdnZHO0 / task(explore)=ses_f7de44b12ffergneqvHoFo2sNK。
观测结果
  • 事件序列为 step_start → text → tool_use(task)×2 → step_finish → step_start → text(聚合) → step_finish；两个 task 调用在同一步（同一消息）发出（call_00…/call_01…），并行执行且均 status=completed；聚合结果为 general 返回 17×23=391、explore 返回 /tmp/opencode 直接条目 29 个。另跑 exp2b 验证嵌套委派：orch → general → explore 三级链，explore 计算 5+5=10 并逐级回传，证明 subagent_depth=2 生效。
量化指标
  • 并行委派 2/2 task 同轮发出（并行度=2）；轮数 2 步（委派 1 步 + 聚合 1 步）；token total 12777 / reasoning 94 / 成本 $0.000305；exp2b 嵌套链实测深度 3 层（depth 0→1→2），token 11776 / 成本 $0.000143。
控制论解读
  • 属于 P 环（分层控制/慢-快双速）——主 agent 做慢规划（分解+路由），worker 做快执行；控制律为任务分解 + 并行执行器阵列，subagent_depth=2 是执行器递归深度限幅（T 环约束 P 环展开）。装配层把单体内核扩展为可并行、可嵌套的分层执行器，P 环由「提示词约定」升级为「runtime 硬支持（task 工具 + depth 限幅）」。

实验3 Reflection 闭环（R 环反转，只读验证）

实验设计
  • 对 Reflection 系统状态机做只读验证，不写入 pending.json；观测指标为三态计数、状态迁移、四层数据结构、内核是否内置 R 环。
执行数据
  • 只读读取 ~/opencode/archive/Reflection/pending.json；静态源为 opencode.jsonc 的 build/plan prompt 内「Build 末尾 Reflection 写入」+「Reflection 自检规则」、command/reflection.md、reflection-worker agent 定义（opencode.jsonc L110）；时间戳 01:41 快照，文件在 01:40:36 被并发 reflection-worker 会话 ses_f7de57ae0ffeXlk1JxAFMSxQbg（日志 run=70b44a03）写入。
观测结果
  • meta 三态为 waiting_count=33 / processing_count=2 / done_count=2（快照时刻）；状态机为 waiting →（build 自检置 processing）→ reflection-worker 处理 → done →（/reflection 人审 yes/edit）→ MEMORY.md；每 cycle.layers = {layerA(GATE/complexity/decisions)、layerB(子Agent JSON)、layerC(MEMORY.md 快照)、layerD(留档报告)}；内核侧 opencode agent list 无 reflection 内置 agent，reflection-worker 由装配层 config 定义；安全证据为日志中 pending.json 的 edit 权限全部来自 reflection-worker 会话 ses_f7de57ae0ffe…，本实验会话 ses_f7de57eec…（agent=general）对 pending.json 仅命中 permission=read，未命中 edit。
量化指标
  • 待处理积压 33 waiting（异步队列，与主流程解耦）；闭环层级为内核 0 个内置 R 环 agent，装配层 +1 reflection-worker + 1 /reflection 命令 + 1 pending.json 队列；人审门控要求 done→MEMORY.md 需 yes/edit 显式确认（写入签名 [src: cycle_id]）。
控制论解读
  • 属于 R 环（反馈/积分环节），呈现R 环反转——内核弱 R（无独立 Critic/反思），装配层补齐异步慢 R 环；控制律为误差（任务经验）不即时回灌，而是入队 pending.json → 延迟批处理 reflection-worker → 人工门控转正，属积分/离散采样反馈，牺牲时延换稳定与去噪。opencode-custom 的 R 环是「外挂式、异步、人审闭环」，用装配层把弱内核 R 补齐为可审计的长期记忆闭环。

实验4 GATE 门控（协议层）

实验设计
  • 在隔离 config 仅注入 auto-mode.md（GATE 协议），以 --agent gate 分别跑简单/复杂任务，观测是否输出 [GATE]、总分与 Daily/Deep 分派是否一致、runtime 是否硬门控；观测指标为 GATE 输出格式、分派一致性、命中率。
执行数据
  • 简单任务 opencode run "计算 2+2 等于多少" --agent gate（XDG_CONFIG_HOME=/tmp/opencode/iso-gate）；复杂任务 opencode run "设计一个跨 5 个模块的重构方案……架构级论证" --agent gate；静态源为 auto-mode.md L7「MANDATORY GATE」、L26 输出格式、L37-38 决策边界（≤12 Daily / ≥13 Deep）、opencode.jsonc L547 注入 auto-mode.md、build prompt「Variant 继承规则」。
观测结果
  • 简单任务仅输出 4，未输出 [GATE]（协议被模型省略）；复杂任务首行输出 [GATE] 范围=5 深度=5 操作=4 风险=2 → 总分=16 → Deep，随后按 Deep 展开架构论证；分派一致性 16≥13 → Deep，与边界表一致 ✅；COMPLEXITY 继承为静态降级验证（auto-mode.md L58 + build prompt 要求 Plan 摘要含 [COMPLEXITY: X/20]、Build 继承，本实验因规避 pending.json 写入未走 plan/build 实机链）。
量化指标
  • 复杂任务 3 步、tools=[bash,glob,bash,glob]、token total 40753 / reasoning 1264 / 成本 $0.001542；简单任务 1 步、token total 10617 / 成本 $0.001223；协议命中率 复杂 1/1、简单 0/1（模型侧省略）。
控制论解读
  • 属于协议层门控（P/E 环的元控制——决定用多大推理预算）；控制律为开环规则 + 模型软执行，runtime 不强制拦截，GATE 是「提示词级」约束而非「看门狗级」硬限幅。GATE 能对复杂任务正确量化并分派 Deep，但简单任务存在漏触发，暴露协议层门控可靠性依赖模型遵循度的稳定性风险（建议将 GATE 缺失纳入 E 环校验或 runtime 提示）。

实验7 架构三层栈端到端（P/E/T 环新机制）

实验设计
  • 控制组为实验2（P 环委派）与实验4（GATE 软门控）；实验组在隔离 config（XDG 全指向 /tmp/opencode/v13-*）装配 arch primary（等价 /arch 执行者，不含 build 的 Reflection 自检链）+ architect-worker subagent + /arch 命令 + architecture-judgment skill + architecture-behavior 指令，用 /arch 日志采集选型 端到端驱动；另以最小 ADR 样例直接驱动门控正/负向判定。观测指标为 skill 是否加载、architect-worker 是否被委派、ADR 是否落盘、门控是否运行且结果正确、三层栈各层是否被引用。

  • 命令 XDG_CONFIG_HOME=/tmp/opencode/v13-config XDG_DATA_HOME=… opencode run "/arch 为一个内部日志采集系统做技术选型（旁路异步采集 / 同步写入 / 混合）…将 ADR JSON 写到 /tmp/opencode/v13-exp/arch_adr.json 后运行 gate_architecture.py --kind adr 门控" --format json；时间戳 2026-09-11 22:10；会话 ses_f6f34e4fdffeu5DvJZ9ATxWK0R。隔离 config 副本含 architecture-judgment skill 17 文件 + /arch 命令 1 + architecture-behavior 指令 1 + arch/architect-worker 两 agent；deepseek provider 经进程环境注入 key，未落盘副本。最小样例为 adr_min_pass.json / adr_min_fail_options.json / adr_min_fail_tec.json。
观测结果
  • 事件序列为 step_start → tool_use(skill=architecture-judgment) → tool_use(task, subagent_type=architect-worker) → …bash(gate_architecture.py --kind adr)… → text → step_finish×12；architecture-judgment skill 被加载 1 次；architect-worker 被委派 1 次；产物 /tmp/opencode/v13-exp/arch_adr.json（ADR-001「内部日志采集系统的采集方式：旁路异步采集优先」，3 options / 11 graph_refs / 2 standards_refs）落盘；主 Agent 运行门控得 6/6 PASS（G-A1~A6 全 PASS，退出码 0）；architect-worker 自身 bash 被 deny（产出方无自验证权限）→ 门控由主 Agent 执行，产出方/验证方天然分离。最小样例直接门控：合规→PASS 6/6、单备选→FAIL（G-A1+G-A2）、TEC 越位→FAIL（G-A5）；gate --selftest 10/10 断言 PASS。

控制论解读
  • 属于 P/E/T 环新机制（分层规划 + 传感器验证 + 执行器门控）。控制律为「行为层触发（前馈规则）+ 显式 /arch 入口 → skill 加载策略 → 子Agent 执行 → 独立传感器 gate 判定」。门控作为 E 环验证器与 P 环产出方物理隔离（architect-worker bash deny 使其无法自证），消除「产出方自审」的自利偏差，是比实验4 GATE（模型软自评）更强的看门狗级硬门控——gate 以确定性脚本 + 正负向断言给出二值判定，不受模型遵循度影响。三层栈各层均被实际引用，P/E/T 环由「提示词约定」升级为「契约（schema）+ 执行器（architect-worker）+ 传感器（gate）+ 行为路由（architecture-behavior）」的完整闭环。

整体控制论结论
  • opencode-custom 的本质是「弱内核 + 强装配层」的分层控制器——P 环被装配层显著强化（task 工具 + subagent_depth=2 把单体内核扩展为可并行、可嵌套的分层执行器阵列，实验2 实测链深 3）；R 环发生反转（内核无独立反思/Critic，装配层用 pending.json 队列 → reflection-worker → /reflection 人审补齐异步慢 R 环，实验3）；T 环通过 MCP 扩展但受 WSL/Windows 环境约束（实验5，仅 2/6 连通）；协议层门控 GATE 是软约束（复杂任务正确分派 Deep、简单任务漏触发，暴露「提示词级门控 ≠ 看门狗级硬限幅」的稳定性风险，实验4）；隔离实验范式（XDG 隔离 + 非 build 代理）证明装配层协议可被安全分片观测，且内核在无装配时仍能独立完成任务（实验1）。
