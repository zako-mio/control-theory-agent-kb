SP

设定值（Setpoint）——自然语言一句话 + 领域专家把意图固化为可验收任务

用户意图 → 可验证子目标
承担角色：把用户的日常语言诉求固化为「专家可自主拆解、可验收」的任务，并由领域专家内置方法保证方向正确。

关键机制

  • 自然语言下达（cloud.tencent.com/product/workbuddy）：用户无需学习专门指令或语法，以日常语言描述需求即可。
  • 自主拆解规划（cloud.tencent.com/product/workbuddy）：自动拆解任务、规划步骤、执行操作，过程中自我校验与修正，直至完成既定目标。
  • 100+ 预置领域专家（cloud.tencent.com/product/workbuddy）：覆盖招聘、投研、前端、法务、营销等领域，内置该领域方法与经验，开箱即用，无需自行编写复杂提示词。
  • 自定义企业专属专家：上传岗位说明书、标准作业流程与知识库，快速构建贴合自身业务的专家（cloud.tencent.com/product/workbuddy）。
  • 交付可验收结果（cloud.tencent.com/product/workbuddy）：输出可供验收的工作成果，而非单纯建议。
控制论映射：KT-ctrl-002（负反馈闭环结构，目标/规格=设定值 r）+ KT-ctrl-041（分层控制结构，专家定领域方法、助理/多 Agent 分解执行）+ KT-ctrl-046（options/SMDP，领域专家把多步流程折叠成一次调用）。
强——自然语言零门槛 + 100+ 专家内置方法 + 自定义专家，设定值固化程度高且对非技术用户友好。弱——「可验收」的判据由专家流程与用户主观共同决定，无机器强制的结构化子目标 schema；营销措辞（如「15分钟交付报告」）未经黑箱实测。
E

E 环 — 评估/传感器（自我校验 + 信息源交叉验证 + AIGC 内容安全 + 安全审计）

评估/传感器
承担角色：为闭环生产「结果是否达标/是否安全合规」的反馈信号，含执行中自我校验、调研交叉验证、内容安全引擎与全流程审计。

关键机制

  • 执行中自我校验与修正（cloud.tencent.com/product/workbuddy）：过程中自我校验并修正直至完成——内建的执行级传感器。
  • 信息源交叉验证（cloud.tencent.com/document/product/1831/134383）：深度调研会拆出检索路径、对信息源交叉验证，再生成结构化报告/竞品矩阵/策略建议——多源交叉验证是显式的评估机制。
  • AIGC 内容安全引擎（cloud.tencent.com/product/workbuddy-enterprise）：对生成内容自动检测与过滤，识别违规/有害/不合规信息。
  • 安全与审计（cloud.tencent.com/product/workbuddy-enterprise）：全生命周期密文管控、全流程可追溯可审计。
  • 合规保障：遵循 ISO、SOC、等保及《数据安全法》等多重标准。
控制论映射：KT-ctrl-006（反馈灵敏度/鲁棒性基础）+ KT-ctrl-035（扰动观测器 DOB，交叉验证在线剔除不可靠信息）+ 交叉 KT-ctrl-012（观测噪声 R，多源验证提升信号可信度）。
强——信息源交叉验证 + AIGC 内容安全 + 全流程审计，评估兼顾「质量」与「合规」，是国内产品中治理意识较强的。弱——「自我校验」的具体信噪比与量化误差未公开，文档级无法验证；交叉验证的独立性与覆盖度未知；无公开的独立 Critic/评审器架构说明。
T

T 环 — 执行器/工具（本地文件操作 + 云端托管 + 多模态 + 连接器）

工具调用/执行器
承担角色：把规划动作落地到「本地文件 + 云端助理 + 腾讯生态连接器」，是直接触碰用户环境与外部系统的环节。

关键机制

  • 本地文件操作（cloud.tencent.com/product/workbuddy）：在用户授权目录范围内直接读取与写入文件，完成资料整理/文档生成/批量处理，成果直接保存本地。
  • 云端 7×24 任务托管（cloud.tencent.com/product/workbuddy）：长任务在云端持续推进，关闭客户端亦不中断（Managed Agents 底座）。
  • 多模态任务处理（cloud.tencent.com/product/workbuddy）：理解/生成文字、图像、表格、代码，解析文档与图表，产出图片、视频等多模态成果。
  • 办公套件原生集成（cloud.tencent.com/product/workbuddy-enterprise）：腾讯文档（上下文共享）、腾讯网盘（AI 资产存管）、乐享知识库（企业知识空间）作为 Agent 原生底座。
  • MCP 数据安全（cloud.tencent.com/product/workbuddy-enterprise）：每次工具/外部系统调用经授权校验，防越权。
控制论映射：KT-ctrl-034（安全边际/硬约束限幅，授权目录范围 + MCP 授权校验）+ KT-ctrl-031（鲁棒稳定性，云端托管抗客户端中断）+ 交叉 KT-ctrl-030（模型不确定性，授权边界提供降级）。
强——本地文件操作 + 云端托管 + 多模态 + 生态连接器，执行能力覆盖个人到组织场景；授权范围与 MCP 校验构成执行边界。弱——文档未公开并发限幅/预算上限等硬约束细节；本地文件写入的风险控制（如沙箱、回滚）未明示；无公开的异质冗余表决机制。
M

M 环 — 记忆/状态估计（乐享知识库 + 网盘资产 + 项目空间沉淀）

记忆/状态估计
承担角色：在跨任务/跨团队中维护组织级知识与上下文，并把调试完成的流程固化为可复用资产。

关键机制

  • 乐享知识库（cloud.tencent.com/product/workbuddy-enterprise）：企业知识全连接、智能治理、安全可控。
  • 腾讯网盘（cloud.tencent.com/product/workbuddy-enterprise）：企业 AI 资产统一存管与可信检索。
  • 腾讯文档（cloud.tencent.com/product/workbuddy-enterprise）：文档即上下文，Agent 原生协作。
  • 流程沉淀全组复用（cloud.tencent.com/product/workbuddy）：把调试完成的专家、Skill 与连接器沉淀至项目空间，一次配置供多人复用。
  • 企业专家/智能体（cloud.tencent.com/product/workbuddy-enterprise）：企业级 Skill/专家/智能体作为持久记忆资产。
控制论映射：KT-ctrl-010/011（状态估计/Kalman 预测-更新，知识库=先验、任务反馈=更新）+ KT-ctrl-014（信息滤波/降维，知识治理按相关性/增量维护）+ 交叉 KT-ctrl-013（分离性）。
强——知识库 + 网盘 + 文档 + 项目空间沉淀，组织级记忆与资产复用体系完整，且有智能治理（去噪/可信检索）。弱——记忆为组织知识资产而非「带不确定度的信念状态」，无显式置信度（P 协方差）；无公开的自动引用校验/过期机制；知识治理细节为营销级描述，未公开机制。
P

P 环 — 规划/分层控制（多 Agent 并行 + 云端助理 + 专家分层）

规划/分层控制
承担角色：作为慢大脑把复杂目标拆给多 Agent 并行推进，并以云端助理与领域专家实现分层执行。

关键机制

  • 多 Agent 并行推进（cloud.tencent.com/product/workbuddy）：同一目标拆分给多个 Agent 同时处理，各自负责一部分，结果统一汇总回流。
  • 云端助理自动拆解分步执行（cloud.tencent.com/product/workbuddy）：会议纪要/数据处理/周报/文件批处理等，下达指令后自动拆解并分步执行。
  • 领域专家分层（cloud.tencent.com/product/workbuddy）：专业判断任务调用对应领域专家，专家自主拆解、调用工具、操作本地文件。
  • 项目空间团队协同（cloud.tencent.com/product/workbuddy）：成熟流程沉淀后供团队共享，从个人到团队能力扩展，跨部门统一推广。
  • 三种交付形态（cloud.tencent.com/product/workbuddy-enterprise）：CodeBuddy（研发编码）+ WorkBuddy（通用办公）+ Managed Agents（云端托管），账户互通、权限共管。
控制论映射：KT-ctrl-041（分层控制结构）+ KT-ctrl-042（递阶/多层控制，多 Agent 各自自主、协调层汇总）+ KT-ctrl-043（时间尺度分离 ε）+ 交叉 KT-ctrl-046（options/SMDP）。
强——多 Agent 并行 + 云端托管 + 专家分层 + 项目空间协同，规划覆盖个人到组织。弱——文档未公开多 Agent 之间是否有 DAG 依赖编排（并行更可能是「分片汇总」而非依赖序）；无公开的 MPC 滚动重规划机制说明；协调与冲突解决细节为营销级描述。
R

R 环 — 反思/反馈闭环（自我修正 + 流程沉淀 + 会话分析）

反思/反馈闭环
承担角色：作为反馈控制器，把执行中的偏差修正回灌，并把成功流程固化为可复用资产。

关键机制

  • 过程中自我校验与修正（cloud.tencent.com/product/workbuddy）：执行中自我校验并修正直至完成——内建纠偏。
  • 流程沉淀复用（cloud.tencent.com/product/workbuddy）：调试完成的专家/Skill/连接器沉淀到项目空间，一次配置多人复用——把反思成果固化。
  • 企业专家/Skill 迭代（cloud.tencent.com/product/workbuddy-enterprise）：企业级 Skill/专家可沉淀与治理，形成组织能力。
  • 安全审计追溯（cloud.tencent.com/product/workbuddy-enterprise）：全流程可追溯可审计，为纠偏提供证据链。
  • 用户反馈闭环：客户之声显示「有时出现报错重试和卡顿」，说明存在重试机制但体验待优化（cloud.tencent.com/product/workbuddy）。 ## 精装房画像总结
控制论映射：KT-ctrl-002（负反馈闭环结构）+ KT-ctrl-020/022（PID 三环节，P=自我校验即时纠偏、I=流程沉淀累积纠偏）+ KT-ctrl-004（误差收敛）。
强——自我校验 + 流程沉淀 + 审计追溯，反思成果可固化为组织资产。弱——文档未公开反思触发的量化阈值与误差收敛判据；用户反馈显示存在报错重试/卡顿，纠偏体验有待实证；无公开的长期偏航累积补偿机制。
